1. **Single-Threaded Engine**:
   JavaScript runs on a single main thread with a single Call Stack. It executes code synchronously line-by-line.

2. **Components of the Runtime Environment**:
   - **Call Stack**: Tracks function execution frames.
   - **Web APIs / Node APIs**: Offloads asynchronous operations (timers, HTTP requests, DOM events) to the browser/environment runtime threads.
   - **Microtask Queue**: Holds callbacks from Promises (\`.then\`, \`.catch\`, \`.finally\`), \`queueMicrotask()\`, and MutationObservers.
   - **Task Queue (Macrotask Queue)**: Holds callbacks from \`setTimeout\`, \`setInterval\`, \`setImmediate\` (Node.js), and I/O tasks.

3. **Event Loop Mechanics**:
   - The Event Loop constantly monitors the Call Stack.
   - When the Call Stack is empty:
     1. It executes **ALL** pending callbacks in the **Microtask Queue** until it is completely empty (including new microtasks queued during execution).
     2. It allows browser rendering/layout repaints if necessary.
     3. It picks **ONE** task from the **Macrotask Queue** and pushes it to the Call Stack.
     4. Repeat loop.`,

- **Synchronous Execution**:
  - Code is executed sequentially, line by line.
  - Each statement waits for the previous statement to complete before moving to the next.

- **Asynchronous Execution**:
  - Code execution is non-blocking. Long-running tasks (network requests, timers, file I/O) are initiated and handled by the browser/Node environment APIs in the background.

  - Once the async task completes, its callback/promise handler is queued for execution via the Event Loop.

    ],
    explanation: `### What is React Fiber?
React Fiber is a complete rewrite of React’s core reconciliation algorithm introduced in React 16. It transforms React's rendering process from synchronous recursive execution into **incremental, schedulable units of work**.

### Problem with Legacy Stack Reconciler:
- Stack reconciler processed element trees synchronously and recursively.
- Heavy component updates locked up the main thread until the entire tree finished re-rendering, causing dropped animation frames and input lag ("jank").

### Core Concepts of Fiber:
1. **Fiber Node as Unit of Work**:
   Each React element corresponds to a Fiber node (a plain JS object containing component type, state, props, child, sibling, return pointer, and lane/priority).
2. **Two-Phase Architecture**:
   - **Render / Reconciliation Phase (Async & Interruptible)**: React walks the fiber tree, computes diffs, and assigns priority. Can be paused, aborted, or restarted.
   - **Commit Phase (Sync & Uninterruptible)**: React applies DOM mutations and executes lifecycle/effects (\`useLayoutEffect\`, \`useEffect\`).
3. **Priority Lanes & Time Slicing**:
   - Updates are categorized by priority (e.g., discrete user interactions like clicks get high priority, off-screen data fetching gets low priority).
   - React slices rendering work into small chunks (~5ms per frame) to yield control back to the browser event loop for smooth user interactions.`,
    codeSnippet: `// Fiber Node Structure (Simplified Conceptual Representation)

  stateNode: any,          // DOM element or component instance
  return: Fiber | null,    // Parent fiber
  child: Fiber | null,     // First child fiber
  sibling: Fiber | null,   // Right sibling fiber
  memoizedState: any,      // Hooks linked list head
  lanes: Lanes,            // Priority bitmask
